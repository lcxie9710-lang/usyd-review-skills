# Learning Workspace — 课程复习工作区（Agent 通用版）

> 一份纯设计文档，不依赖任何特定 Agent 的工具或路径约定。
> 任何能读写文件、能向用户提问的 Agent 都可以执行。

---

## 1. 工作区搭建

### 1.1 询问用户（一次一个问题）
1. 课程代码 + 名称（如 COMP9123 Data Structures & Algorithms）
2. 目标目录——自动从当前工作目录推断，或让用户指定
3. 考试形式——MCQ？简答？开卷/闭卷？是否允许 cheatsheet？

### 1.2 创建目录结构
```
{course-dir}/
├── AGENTS.md       ← 入口：概览、约束、会话流程
├── PROGRESS.md     ← 当前进度
├── DECISIONS.md    ← 重要决策及原因
├── REVIEW.md       ← 易遗忘重难点，期末集中复习
├── TOOL.md         ← 本地工具索引
├── tool/           ← 复习工具脚本
├── notes/          ← 各周知识笔记
│   ├── Week01-{Topic}.md
│   └── ...
└── materials/      ← 原始材料（只读，绝不修改）
    ├── lectures/
    ├── transcripts/
    ├── exercises/
    └── exams/
```

## 2. 材料收集

1. 检查 `materials/` 下各子目录有什么
2. 向用户展示缺口：
   ```
   lectures/        ✅ 3 PDFs
   transcripts/     ❌ 空 — 有录音转录稿吗？
   exercises/       ❌ 空 — 有练习题吗？
   exams/           ⚠️ 1 PDF — 有几份模拟卷？
   ```
3. 引导用户把文件放入对应目录，或告知路径
4. 材料到位前不开始教学

---

## 3. 意图路由（每次会话必须执行）

材料齐备后，**主动向用户提问**，根据答案进入不同模式。提问时给出可点击或字母选项：

> "这次想怎么复习？"
>
> A. 从零开始学，一个知识点一个知识点过
> B. 先做这周的练习题，根据错题针对性补（需 exercises/ 有内容）
> C. 直接刷模拟卷/真题，以卷为纲（需 exams/ 有内容）
> D. 时间紧，快速过一遍考点就行
> E. 只练 MCQ 选择题（需考试为全 MCQ 或用户指定）

**规则**：只展示前提条件满足的选项。用户选择后记入 DECISIONS.md。用户随时说「换个模式」即可切换。

## 4. 五种复习模式

### Mode A — 最小知识点逐个过
**适用**：从零开始、基础薄弱

1. **先读完所有材料**（讲义 + 转录）再开始教
2. 每次只讲**一个知识点**（一个概念 / 一张表 / 一组对比）
3. 讲完等待用户说「继续」再进下一个（语气温和，不说「清楚了吗？」）
4. 一个章节所有知识点讲完后 → 做 MCQ 选择题（一次一题，给 4 个选项）
5. 一周所有章节讲完后 → 写 `notes/Week{NN}-{Topic}.md`
6. 需要 cheatsheet 的话：每讲完一节立刻追加，不等最后

### Mode B — 以练代学
**适用**：有练习题、想先诊断再补

1. 提取本周练习题（保持英文原文）
2. 对照真题格式过滤——跳过题型不一致的题并说明原因
3. **一次一题**呈现，用户作答 → 简短反馈 → 记下错因，继续下一题
4. 错题记入笔记的「错题本」区域
5. 全部做完后：错题深入讲解，已掌握的部分简单带过
6. 生成 `notes/Week{NN}-{Topic}.md`

### Mode C — 模拟卷逐题精讲
**适用**：有模拟卷、以卷为纲

1. **先检查** PROGRESS.md 和之前对话中用户有无自己的解法（用户解法 > 官方答案）
2. 显示完整题目原文（不压缩、不提炼"核心考点"）
3. 逐步引导：第一步/第二步/第三步… 边推边讲
4. 用户提出不同解法 → 验证，正确就采用
5. 每题讲完 → 写完整双语答案到 CHEATSHEET.md，**默认满分级详细，不主动压缩**
6. 显示答题进度条
7. 逐小问模式：用户说「一小问一小问发给我」→ 每次只给一个子问题

### Mode D — 快速串讲
**适用**：时间紧

1. 先扫真题确定考点范围
2. 只讲考点相关内容
3. 节奏稍快但仍按节停顿
4. 生成笔记 → 跳过 MCQ 和练习 → 直接进下一周

### Mode E — 全 MCQ 模式
**适用**：考试全是选择题

1. Cheatsheet 用对比表（`| 中文 | English |`）
2. 按节讲解 → 立刻写入 cheatsheet → 下一节
3. 讲完做 MCQ，错题解释**每个**干扰项为什么错

## 5. Cheatsheet 速查表管理

### 何时创建
- 考试允许带 cheatsheet
- 用户明确要求

### 格式
- **源文件**：`CHEATSHEET.md`，两列表格 `| 中文 | English |`
- **打印版**：`CHEATSHEET.html`，A4 竖版三栏，中英合并，带字号缩放工具栏
- **增量写入**：每节讲完立刻追加，不等最后

### 默认：满分级
- 所有条目默认写完整——用户能直接抄到卷子上的详细程度
- **绝不主动压缩**，除非用户说「这个缩一下」

## 6. 文档模板

### AGENTS.md
```markdown
# {Course Code} {Course Name} — 期末复习工作区

## 项目概览
- **课程**: {Course Code} {Course Name}
- **内容**: {简要范围}
- **目标**: 系统化期末复习
- **语言**: 简体中文

## 目录
[目录结构]

## 硬约束
1. `materials/` 下一切只读，笔记写入 `notes/`
2. 任何时候只有 1 个任务「进行中」
3. 状态由文档描述，不依赖会话记忆
4. 解答优先基于原始材料
5. 引导式教学：先让用户推理，放弃时才给答案
6. 同一知识点被追问 ≥3 次 → 记入 REVIEW.md
7. 每个任务生成笔记 `notes/Week{NN}-{Topic}.md`

## 每次开始
1. 读 PROGRESS.md → 当前状态和下一步
2. 读 DECISIONS.md → 重要决策
3. 确认本次任务、验收标准 → 标记进行中
4. 开始

## 每次结束
1. 更新 PROGRESS.md
2. 重要决策记入 DECISIONS.md
3. ≥3 次追问的知识点记入 REVIEW.md
4. 检查 5 份文档无矛盾
5. TOOL.md 与 tool/ 目录一致
6. 确保下个 Agent 只读文档即可接手

## 任务格式
### T{NN}: {描述}
- 状态: pending | in_progress | completed | blocked
- 验收标准: {可验证条件}
- 开始: {时间}
- 完成: {时间 或 -}
- 备注: -
```

### PROGRESS.md
```markdown
# {Course Code} — 复习进度

> 开始: {日期}
> 当前状态: {一句话}
> 下一步: {做什么}

## 任务列表

### T01: {描述}
- 状态: pending | in_progress | completed | blocked
- 验收标准: {可验证条件}
- 开始: -
- 完成: -
- 备注: -
```

## 7. 教学风格（内嵌规则）

1. 一次一个知识点——「降低我单次复习的难度」
2. 选择题用 4 选 1 字母选项，一次一题
3. 用户解法 > 官方答案——先查之前记录
4. 温和语气，不说「清楚了吗？继续？」
5. 练习题/真题保持英文原文
6. 引导优先——让用户先想，放弃才给答案
7. 同一知识点被追问 ≥3 次 → 自动记入 REVIEW.md
8. 模拟卷练习时显示进度条
9. Cheatsheet 按节增量写入

## 8. 常见错误

- ❌ 不要创建 Makefile/脚本——这是文档驱动工作流
- ❌ 材料没读完就开始教学
- ❌ 一次倾倒多个知识点
- ❌ 教学和测试穿插——先吸收完再测
- ❌ 未经允许压缩 cheatsheet
- ❌ 不看用户之前的解法就讲官方答案
- ❌ 翻译练习题——保持英文原文
- ❌ 一次给多道 MCQ
- ❌ 在 AGENTS.md 里写超过 80 行——它是入口卡片不是设计文档
